1. Прототип шутера от третьего лица, название MUTARA.

Цель уровня поднять ключ-карту, выжить, и активировать ее на компьютере. Смерть - поражение.

3. Версия unity - 2022.3.62f2.

4. Собирается стандартно для windows, при первом открытии проекта генерируется скрипт TPSInputActions его следует удалить, так как в проекте он уже присутствует. Проверил запуск и сборку из чистого клона, все ок. Файлы .dll и .meta на месте.

5. Управление:

AWSD - перемещение, пробел - прыжок, ctr - приседание, shift - бег, R - переpарядка, E - действие, esc - пауза/меню, tab - карта, левая кнопка мышки - стрельба, правая кнопка мышки - ADS камера (прицеливание).

8. Реализовано:

2.1 Зависимости - Zenject, 3 инсталлера, проектный и сценовые, с разделением по ответственности. Через контейнер регистрируются: сервис ввода, сервис звука, сервис игрока,
собственные фабрики врагов, снарядов, пикапов, интерфейсы и т.п.

2.2 Асинхронные операции через корутины (описаны в п.10).

2.3 Паттерны проектирования, реализованы: State Machine, Object Pool, Factory/Abstract Factory, Observer.

3.1 Камера от третьего лица через Cinemachine 3rd Person Follow, свободный обзор мышью, (режим прицеливания ADS, приближение, сужение FOV, замедление поворота).

Движение: WASD относительно камеры, бег, приседание, прыжок, гравитация.

В обычном режиме персонаж поворачивается по направлению движения, в режиме прицеливания строго по камере, ноги двигаются strafe-анимациями.
Весь ввод через Input System, отдельный .inputactions-ассет, карты действий (Player , UI переключение карт при паузе).

Анимации: Idle, Walk/Run вперёд-назад-вбок через 2D Blend Tree, Aim, Fire, Reload, Hit Reaction, Death, Jump и др. Стрельба и перезарядка на отдельном слое Animator с AvatarMask.

Здоровье, получение урона, смерть, экран поражения, экран победы.

3.2 5 дистанционных типов оружия с разными снарядами, типами стрельбы, эффектам (вспышка выстрела, трассер, гильзы, декаль
попадания, искры/кровь/пыль в зависимости от типа поверхности) и 1 оружие ближнего боя.

Свои звуки у каждого: выстрел, «магазин пуст», перезарядка, удар ближнего боя (по воздуху и по цели разные), взрыв.
Смена оружия: цифры и колесо мыши, с анимацией убирания-доставания, доступно только подобранное. 

Патроны раздельные по типу оружия; при нуле щелчок и невозможность стрелять.

Граната гранатомета наносит урок противнику, разрушающимся объектам и задевает игрока (реализовано осознанно).

Пул объектов для снарядов, гильз, трассеров, декалей и VFX. Декали ограничены по времени жизни.

3.3 Два разных типа противников: Стрелок и боец ближнего боя.

Стрелок (дальний бой) имеет состояния Patrol (по точкам), Alert (заметил, доворачивается). Combat (держит дистанцию, стреляет стреляет одиночными с перерывом). TakeCover (при HP ниже порога 30% уходит за укрытие). Dead - смерть. Search (потерял игрока идёт к последней известной позиции, осматривается, возвращается на
патруль). Стрельба с упреждением, промах-разброс.

Штурмовик (ближний бой). Idle/Sleep, Chase (сближение до attackRange ), Attack (удар с кулдауном, урон в момент кадра анимации через Animation Event). Backstep (отход после удара). Stunned (от взрыва и дробовика). Dead смерть.

Каждое состояние - отдельный класс с общим интерфейсом (переходы — в машине состояний).
Поле зрения: радиус обнаружения + угол обзора.
Gizmos: радиус обзора, конус угла обзора, радиус атаки, линия до текущей цели, маршрут патруля. Цвет гизмо меняется в
зависимости от текущего состояния.

Анимации Mixamo под каждое состояние, звуки (обнаружение цели, атака, шаги, получение урона,
смерть).
Попадание в голову - повышенный множитель урона.
Спавн - через собственную фабрику, внедрённую контейнером волнами
по таймеру.

3.4 3 зоны - открытая территория, внутреннее помещение, технический этаж, переход между ними через двери и лифт.
Освещение и эмбиент в зонах различаются.

Взрывающиеся бочки - урон по радиусу + цепная реакция и AddExplosionForce, VFX, звук.
Разрушаемые ящики (разлёт обломков, обломки убираются по таймеру).

Физические препятствия (ящики) которые можно толкать.

Триггер-зоны: урон (газ), спавн волны, скриптовое событие (открытие барьера).

Настроенная матрица столкновений, отдельные слои для
игрока, врагов, хитбоксов, окружения, снарядов, интерактива. Лифт не проваливает персонажа. 

3.5 Двери - раздвижные (две створки, открытие по подходу, барьер — по ключ-карте.
Лифт - вызов по кнопке, игрок едет вместе с платформой.

Ловушки — (газовая). Барьер - (луч + движения эмиттера).

Пикапы — покачивание вверх-вниз и вращение, при подборе подлёт и уменьшение масштаба.

UI - появление панелей меню, подсветка кнопок, тряска HUD при уроне, пульсация полосы здоровья при низком HP и др. анимации интерфейса.

3.6 Рейкасты применяются:
Хитскан-стрельба и определение точки и нормали попадания.
Определение типа поверхности - от него зависят декаль, эффект попадания и звук шага (бетон,
металл, плоть).

Луч интеракции из камеры — подсветка объекта и подсказка «нажмите E».
Проверка прямой видимости у ИИ (есть ли стена между врагом и игроком).
Поиск укрытия у ИИ.
Ground Check персонажа Raycast вниз — приземление, звук шагов.

3.7 Система подбора предметов
Аптечка - восстановление здоровья по тикам асинхронно, с отменой при смерти.
Патроны - раздельно по типам оружия, с ограничением максимального запаса.
Оружие - при подборе появляется в инвентаре и становится доступно для смены; повторный
подбор даёт патроны.
Ключ-карта - открывает барьер, отображается в HUD, завершает миссию при активации ПК.
Общий интерфейс, подбор по триггеру.
Спавн пикапов через собственную фабрику. Дроп с убитых врагов и ящиков по шансу (настраивается в конфиге), визуальный и звуковой отклик при подборе. Предмет не подбирается, если
ресурс уже максимален. Модель инвентаря отделена от UI, UI обновляется по событию (Observer).

3.8 Миникарта и 2D

Миникарта в HUD: отдельная ортографическая камера, смотрящая на уровень сверху, с
Culling Mask только на нужные слои, рендер в области обзора и высота настраиваются.
RenderTexture ,RawImage в углу экрана.

Маркеры - 2D-спрайты (как UI-элементы поверх RawImage ): 
игрок (стрелка, поворачивающаяся по направлению взгляда), противники (которые заметили игрока), ключ-карта, аптечки, точка выхода. Часть маркеров пулятся.
Режим "north-up".
Clamp маркеров к краю миникарты со стрелкой-указателем для целей за пределами радиуса.

Полноэкранная карта по Tab — оверлей с легендой, отображает всю зону.
3D геометрия основной сцены не протекает в миникарту и наоборот.

AudioMixer с группами: Master, Music,SFX , UI , Ambient
Эффект Reverb на группах SFX Ambient/

SFX в помещениях (закрытые зоны звучат иначе, чем открытые -
переключение через Snapshots), Lowpass при низком здоровье и оглушении от взрыва,

Набор звуков: выстрелы (разные у каждого оружия), удары ближнего боя,
перезарядка, «пусто», взрывы, шаги игрока с зависимостью от поверхности (тип берётся рейкастом

3D-звук: 
Spatial Blend = 1 для всего мирового аудио, осмысленное.

3.10 UI и игровой цикл

HUD: здоровье, патроны (в магазине и в запасе), текущее оружие и иконки доступных, миникарта,
динамический прицел (расширяется при разбросе и беге), индикатор направления полученного
урона, счётчик задачи, подсказки интеракции.

Экраны: главное меню (Играть / Настройки / Выход), пауза (с Time.timeScale и переключением карты действий Input System), поражение, победа, настройки (громкость по группам,
чувствительность мыши, инверсия оси).

Асинхронная загрузка уровня с прогресс-баром.

Игровой цикл: цель поднять ключ-карту, добраться до точки эвакуации, победа и поражение обрабатываются, есть рестарт и выход в меню. Курсор корректно
блокируется и разблокируется.

7. Паттерны:

7.1. State Machine | EnemyStateMachine, ShooterCombatState, ShooterSearchState, ShooterPatrolState, ShooterTakeCoverState, ShooterBackstepState | Используется для управления состояниями противников. В зависимости от ситуации противник переключается между патрулированием, поиском игрока, боем, отходом и укрытием. Например, ShooterCombatState переводит противника в ShooterSearchState, если игрок потерян, и в ShooterTakeCoverState при низком здоровье.

7.2. Object Pool | ProjectilePool, SpitProjectilePool | Используется для повторного использования часто создаваемых объектов, например снарядов. Вместо постоянного Instantiate/Destroy снаряды берутся из пула и после использования возвращаются обратно.

7.3. Factory | EnemyFactory, PickupFactory, IEnemyFactory, IPickupFactory | Используется для централизованного создания игровых объектов. PickupFactory предоставляет отдельные методы создания аптечек, боеприпасов и оружия, а конкретные префабы хранятся в конфигурации.

7.4. Observer | Health, AmmoChanged, CurrentWeaponChanged, HealthChanged, Died, DamageReceived | Используется для событийной связи между игровыми системами. Например, Health сообщает об изменении здоровья и смерти через events, а интерфейс может реагировать на эти события без прямой зависимости от логики нанесения урона.

7.5. Strategy* | Системы оружия, типы снарядов и обработки урона | Используется для возможности задавать различное поведение отдельных игровых механик без изменения основного кода. Разные виды оружия используют собственную логику атаки и обработки снаряда/урона.
  
7.6. Command* | InputService и система обработки игрового ввода | Используется для отделения получения пользовательского ввода от игровой логики. Игровые системы работают с действиями ввода (Move, Jump, Fire, Aim, Interact и тд.), а не непосредственно с клавиатурой или мышью.

7.7. Decorator/Chain of Responsibility* | Система обработки урона и DamageHitbox | Используется при прохождении урона через дополнительные обработчики. Например, при попадании сначала может обрабатываться специальный DamageHitbox, после чего используется обычная система Health/IDamageable.

Strategy, Command и Decorator/Chain of Responsibility в проекте реализованы как архитектурные подходы, а не как классические паттерны.

8. Zenject:

Zenject используется для централизованного управления зависимостями, повторного использования общих сервисов и построения модульной архитектуры проекта.
Через ProjectInstaller, GameInstaller, MainMenuInstaller регистрируются глобальные сервисы, фабрики, конфигурации и другие зависимости.

ProjectInstaller предоставляет единый InputService для обработки ввода. 
GameInstaller отвечает за зависимости игровой сцены: PlayerTarget, EnemyStateMachine, EnemyFactory, PickupFactory, DropTable и звуковую систему.
MainMenuInstaller предоставляет звуковой сервис и библиотеку UI-звуков для главного меню.

Для фабрик используются интерфейсы (IEnemyFactory, IPickupFactory, ISoundService), что снижает связанность компонентов и позволяет заменять конкретные реализации без изменения потребляющего кода.
