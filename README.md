1. Прототип шутера от третьего лица, название MUTARA.

2. Версия unity - 2022.3.62f2.

3. Собирается стандартно для windows, при первом открытии проекта генерируется скрипт TPSInputActions его следует удалить, так как в проекте он уже присутствует. Проверил запуск и сборку из чистого клона, все ок. Файлы .dll и .meta на месте.

4. Управление: AWSD - перемещение, пробел - прыжок, ctr - приседание, shift - бег, R - переpарядка, E - действие, esc - пауза/меню, tab - карта, левая кнопка мышки - стрельба, правая кнопка мышки - ADS камера (прицеливание).

5. Реализовано:
2.1 Зависимости - Zenject, 3 инсталлера, проектный и сценовые, с разделением по ответственности. Через контейнер регистрируются: сервис ввода, сервис звука, сервис игрока,
собственные фабрики врагов, снарядов, пикапов, интерфейсы и т.п.

2.2 Асинхронные операции через корутины (описаны в п.10).

2.3 Паттерны проектирования, реализованы: State Machine, Object Pool, Factory/Abstract Factory, Observer.

3.1 Камера от третьего лица через Cinemachine 3rd Person Follow, свободный обзор мышью, (режим прицеливания ADS, приближение, сужение FOV, замедление поворота).

Движение: WASD относительно камеры, бег, приседание, прыжок, гравитация.

В обычном режиме персонаж поворачивается по направлению движения, в режиме прицеливания строго по камере, ноги двигаются strafe-анимациями.
Весь ввод через Input System, отдельный .inputactions-ассет, карты действий (Player , UI переключение карт при паузе).

Анимации: Idle, Walk/Run вперёд-назад-вбок через 2D Blend Tree, Aim, Fire, Reload, Hit Reaction, Death, Jump и др. Стрельба и перезарядка на отдельном слое Animator с AvatarMask.

Здоровье, получение урона, смерть, экран поражения, экран победы.

7. Паттерны:
Паттерн                              Класс/файл                                                                                                                   Где и зачем используется

State Machine                        | EnemyStateMachine, ShooterCombatState, ShooterSearchState, ShooterPatrolState, ShooterTakeCoverState, ShooterBackstepState | Используется для управления состояниями противников. В зависимости от ситуации противник переключается между патрулированием, поиском игрока, боем, отходом и укрытием. Например, ShooterCombatState переводит противника в ShooterSearchState, если игрок потерян, и в ShooterTakeCoverState при низком здоровье.
Object Pool                          | ProjectilePool, SpitProjectilePool                                                                                         | Используется для повторного использования часто создаваемых объектов, например снарядов. Вместо постоянного Instantiate/Destroy снаряды берутся из пула и после использования возвращаются обратно.
Factory                              | EnemyFactory, PickupFactory, IEnemyFactory, IPickupFactory                                                                 | Используется для централизованного создания игровых объектов. PickupFactory предоставляет отдельные методы создания аптечек, боеприпасов и оружия, а конкретные префабы хранятся в конфигурации.
Observer                             | Health, AmmoChanged, CurrentWeaponChanged, HealthChanged, Died, DamageReceived                                             | Используется для событийной связи между игровыми системами. Например, Health сообщает об изменении здоровья и смерти через events, а интерфейс может реагировать на эти события без прямой зависимости от логики нанесения урона.
Strategy*                            | Системы оружия, типы снарядов и обработки урона                                                                            | Используется для возможности задавать различное поведение отдельных игровых механик без изменения основного кода. Разные виды оружия используют собственную логику атаки и обработки снаряда/урона.
Command*                             | InputService и система обработки игрового ввода                                                                            | Используется для отделения получения пользовательского ввода от игровой логики. Игровые системы работают с действиями ввода (Move, Jump, Fire, Aim, Interact и тд.), а не непосредственно с клавиатурой или мышью.
Decorator/Chain of Responsibility*   | Система обработки урона и DamageHitbox                                                                                     | Используется при прохождении урона через дополнительные обработчики. Например, при попадании сначала может обрабатываться специальный DamageHitbox, после чего используется обычная система Health/IDamageable.

Strategy, Command и Decorator/Chain of Responsibility в проекте реализованы как архитектурные подходы, а не как классические паттерны

8. Zenject:
Zenject используется для централизованного управления зависимостями, повторного использования общих сервисов и построения модульной архитектуры проекта.
Через ProjectInstaller, GameInstaller, MainMenuInstaller регистрируются глобальные сервисы, фабрики, конфигурации и другие зависимости.

ProjectInstaller предоставляет единый InputService для обработки ввода. 
GameInstaller отвечает за зависимости игровой сцены: PlayerTarget, EnemyStateMachine, EnemyFactory, PickupFactory, DropTable и звуковую систему.
MainMenuInstaller предоставляет звуковой сервис и библиотеку UI-звуков для главного меню.

Для фабрик используются интерфейсы (IEnemyFactory, IPickupFactory, ISoundService), что снижает связанность компонентов и позволяет заменять конкретные реализации без изменения потребляющего кода.
